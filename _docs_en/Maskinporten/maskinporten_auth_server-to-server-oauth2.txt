Introduction
The machine gate offers functionality for server-to-server authorization of APIs based on RFC7523 Json Web Token (JWT) Profile for OAuth 2.0 Client Authentication and Authorization Grants.

Consumers and API providers can use this functionality to manage access in cases where the information values the API offers are regulated by a legal basis, and does not require the consent of the user.
Description of flow

sequence chart
  Note over client: Generate and sign JWT
  Client ->> Machine Gate: Use JWT to request token
  Note over the machine gate: Valides business certificate and perform access control
  Machine gate ->> client: return access_token
  Client ->> API: Use token against API
  API ->> Client: Result of API -Kall


In this scenario, a client wants to use a resource (API) offered by a resource server. Access (authorization) of the API is issued by an authorization server, in this case the machine gate. In order to access the resource, the client must request an access_token from the authorization server that the client can then use for access the resource in question.


The flow starts with the client having to generate a JWT-based Tokn request (JWT-Bearer Authorization Grant). This contains information on what resources (Scope) the client wants to access and is signed with the client's business certificate.


When the authorization server receives the token request, the first will validate the validity of the JWT. Subsequently, the business certificate (used for signing the JWT) will be validated and implicit client authentication on the basis of this.


If the authenticated client has access to the requested resources, a self-contained access_token to the client is returned to


The client can now access the desired resource when using the access_tokenet.


The resource server must now validate the received Access_tokenet locally.


If the access_token is valid, the requested resource can be returned to the client.
