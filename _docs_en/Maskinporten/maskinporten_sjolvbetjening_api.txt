Self-service as API consumer
In order to use self-service via API, the company must be awarded an administrative client from Digdir. The API is secured with OAuth2 with the use of a business certificate. Note that a valid test business certificate must be used in the test environments.
To manage integrajons/clients, the administration client must have access to one or more scopes:
| Scope | Description |
|-|-|
| Idports: DCR.Read | provides access to read client registrations for clients bound to the same org.no. As given in the access_token. Also provides reading access to Onbehalfof registrations |
| Idports: DCR.Modify | Provides access to change client registrations for clients bound to the same org.no. As given in the access_token. Also provides reading access to Onbehalfof registrations |
| Idports: DCR.Write | Provides access to create new client registrations for clients bound to the same org.no. As given in the access_token. Also provides reading access to Onbehalfof registrations |
| Idports: DCR/Onbehalfof: Write | Provides access to view, create, change and delete the onbehalfophophophonia belonging to a given client. Does not allow to change other parameters on the client itself. |
| IDPORT: DCR.SUPPLIER | Gives suppliers access to view, create, change and delete independent OIDC integrations for other organizations. Own org.no is linked to these integrations.  |
Contact serviceedesk@dir.no to access.
Register the client
Record client using business certificate
In order to register a client through our self-service apia, you must first create a self-service client.  See {{site.baseurl}/docs/idports/oidc/oidc_api_admin.
Then you can create the machinery integration as follows:
`` `
Post https://api. Cooperation.digdir.no/Clients/
{
   "Integration_Type": "Machine Gate",
    "Client_name": "Oidc_difi_jb_test",
    "Description": "New Integrajson again.",
    "Token_endpoint_Auth_method": "Private_key_jwt",
    "Grant_Types": [
        "Urn: IETF: Params: OAuth: Grant-Type: JWT-Bearer"
    ], ],
    "Scopes": ["Difitest: API3", "Difitest: API4"]
}
`` `
The machine gate will respond with an auto-generated client_id, for example  
Registering client using your own key
To avoid spreading the business certificate around to many systems, you can create your own asymmetrical keys related to a single integration.
This must be done in two steps: First you create a client who in the example above, and then you create a key set on this:
`` `
Post/Clients/238259D7-F0AB-4BD5-B253-0F0159375096/JWKS
{
  "Keys": [
    {
      "KTY": "RSA",
      "E": "Aqab",
      "Use": "Sig",
      "Kid": "My_egen_nokkel",
      "Alg": "Rs256",
      "N": "LGC-DGNL9L9PCSB6EW5MF23AISS09Q7MXRE9Q9DAZSIN9IJQJQJMKWDYSPOYW3G_RSX2A74CG_Q3ITSSM0CO9IJ0 Lqp8gjoii9i8syi6anbkk6fisr1adzbsggrm1-zmrnvsj811sntdkbgx8zxvrjm4f6d2kwl3Tenv0crrvtpho 0SRMIMKBVBDAWPYQC64SQDVARY6XILPHD-DA2N2N2CL6VRQVNS7DYD8-C2TEYGGB_TASRVSORX9GF5CZ-HLNHF IgG2qqyzaljyfowppg5RYBP9BAWG9VFLLUFD_Y6VVZ0TQVFAYJ67NFZ_W4RXY-MDRGERKHJCQ81GKMVZQ5FQ "
    }
  )
}
`` `
'Kid' values must be unique within the client's key set. 
Note! There are different software for key creation and exporting of public key. This will not be mentioned in Digdir's technical documentation.
Public key in PEM format must be converted to JWK using, for example, JWK Creator before it can be put on the client.
