Test strategies
There are several possible strategies to test e -dissemination and they often fit in different phases of the work of using
Em shape.
Test in a local mock environment
Em shape offers setup for a local Mock environment that allows a tested integration point. All external services are
Mocked away. The Mock environment is recommended as a support for development and early paving testing. It is important to note that
Testing in the mock environment is not sufficient to verify that an integration towards e-mooring works. See description
of how to use the Mock environment:

EFM-MOCKS (external link)

Test in the Emsynings Test Environment
In order to verify that an integration against e -dissemination works, it is necessary to test in the Emsynidling test environment. 
In order to test in the Emsynings test environment, one must install an integration point and configure it to use the test environment.
Regular installation guidance can be followed, but before you start, you have to make sure you have a full test business. One
Must first choose whether one wants to use real or synthetic organization number. If one does not have a need to use
Real organization number In its test environment, the use of synthetic organization number is recommended.
Test in the Emsynings Test Environment with Real Organization Number
The test environment for e -dissemination messaging is realized using a separate messaging service in Altinn dissemination
Production environment. Altinn dissemination production environment only supports real organization number.
For Altinn Digital Post and KS Svarut and Replyer, the test environment is used that only supports synthetic organization number. One
Thus, cannot use real organization numbers against all messaging services used by eMespecting. One can anyway
Use all messaging services by entering the username and password for test business at Altinn Digital Post with
An organization number other than the integration point runs. The same goes for KS Svarut and Replyer.

Test in the Emsynings Production Environment
A business ready to use e -dissemination or to make changes to its layout is recommended to do
Some simple tests in the production environment to confirm that communication, access and certificate setup work as expected. 
When testing before the first use of a new messaging service, it may be okay to keep in mind:

This should be done with a person from the archive who is familiar with the case/archive/professional system of the business.
Agree with serviceedesk@dir.no when you want to verify so we can open access on our site. Define a time frame for testing.
Remember to test all messaging services that the business will use
Feel free to test more shipments per message type and varying size, attachments, etc.
NB! When testing takes place, the business can receive real shipments during this period. It is important that the business is aware of this so that they do not miss important shipments.
If something should not work immediately notify serviceedesk@igdir.no so we can remove access and troubleshoot the problem.
Real shipments received during the test period without everything working must be checked. Notify the sender and ask them to resubmit.
How do I know it works?
In case of shipments, one must hear with the recipient that the message has arrived
Upon receipt, the messages should be pushed from the integration point into the case/archive/subject system
Once you have verified that both receiving and consignments work, you will report to serviceedesk@dir.no.

Test setup
Note that if necessary for multiple installations of the integration point (eg two developers with each installation) in
The same environment will find that the installations "steal" messages from each other if they share test operations. One
Can solve this by using channels or by using a test business per installation.
Depending on which messaging services are used, test users and test businesses will be needed to send to and
receive from:
