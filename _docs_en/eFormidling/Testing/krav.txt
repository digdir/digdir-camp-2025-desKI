These requirements apply regardless of which process (s) are supported.

Send message to a recipient using eFonsemidling
Verify that the message is marked as failed
Verify that the user who sent the message is told that message failed without requiring the user even actively checking the status of the message

Verify that the following categories are incorrectly handled:

Synchronous errors, for example if address lookup fails, send e.g. to address that does not exist
Asynchronous errors, for example, if authentication fails to the current messaging service, add e.g. in the wrong username of the messaging service in the configuration before sending a message
Lifetime expired, for example if the recipient leaves/fails to process message, send e.g. to QA integration point and wait for lifetime expires

Verify that the system follows asynchronous statuses (including error statuses) related to a message until it has received one of the following statuses:, or. Note that the status will be able to come several days and weeks after the message has been sent and that one must therefore pollen over an undefined period if it is desired.
