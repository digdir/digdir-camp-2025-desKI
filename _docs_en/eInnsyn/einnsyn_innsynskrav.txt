When an end user orders access requirements for a business, this should be received by e-mail. This e-mail has an explanatory text on which document it has been ordered. Attached. Attached to the email there is an Order.xml file to be imported to the case archive system. Whether this is done automatically or manually is up to each content provider. Subsequently, the file must be processed by archives and answers to the access requirement must be sent to the access to access the e-mail address.
How does it work?
When an end-user orders an access requirement, the Directorate of Digitization will generate its e-insight client generate an order and send it to the Directorate of Digitization's integration point. This integration point will thus encrypt, sign and pack the message and then send it via Azure Service Bus to the recipient's integration point. Here it will be decrypted and passed on to the recipient's e-insight client. This will contact an internal SMTP server and ask it to send your order. There will then be an e-mail from this email server, but with the sender e-mail address "no_reply@e insyn.no". This email goes to the address specified on eilsyn.no below. Then the file must be imported into the case archive system. 

If you do not receive the email, you may want to check the spam/junk mail folder.
By direct integration (without e-insight client)
Professional system that supports direct integration can retrieve Order.xml directly from the integration point.
Extended variant of Order.xml
We have developed two variants of Order.xml. Version 1 is the original and "default". If desirable and support to receive the extended version (version 2), it can be set/changed in the insight Admin by a business administrator:
