Here you will find information about test users that can be used for testing the ID port integrations in the verification environment test.
Test time
We recommend that all customers use test time when testing the ID port. Test time offers to select security level. 

Test time supports login with synthetic personal identifier (+80 on the month-digit), and the risk of mixing test and production data is then avoided.
Test time has no password, so you don't have to contact Digdir to assign, created or reset users.
We recommend using Tenor Testdata search to find test users from the Test People's register.
Synthetic test users can also be used for "headless login" for automated API testing.  This is described further down this page.
Minid
Create the test user even in the test environment test
It is possible to create a test user in MinID on his own in the new test environment Test. One must then follow the usual flow for ordering MinID. This assumes that one uses synthetic personal identifier (+80 on the month-digit). PID must be obtained from tenor test data searches. 
Approach

Press the login image in test in MinID "Order new MinID". Or use direct link: https://activation letter.test.minid.no/order
Fill in synthestic personal identifier
Order activation letter. You then get an activation code.
{ % Include note.html content = "In the production environment, the end user will be sent activation code by mail. In the test environment, the activation code comes immediately. In both cases, the user must enter the page of the activation letter page to recover code and complete new user creation in minide" %}
Post the activation code in "Register activation letter" 

Static OTC - test
There is functionality for static OTC in the test environment test. This applies in login flow and forgotten password flow. It is only possible for test users with synthetic personal fibrator. In addition, OTC is sent by SMS to listed mobile phone number on the user a logs in with. Any email in forgotten password flow. 
The contact information (e-mail, tel) that is created on a mini-Test user is registered in the Contact and Reservation Register (KRR). Read more about how to change contact information on a test user on our pages about KRR.
