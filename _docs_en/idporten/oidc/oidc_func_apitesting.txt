The ID port in test environments offers "headless login"/automatic login where tokens can be issued without user interaction to synthetic test users.  This functionality should only be used to simplify the testing of APIs protected by the access_token from the ID port.
This is the "full" tokens that can then be introspectes, refreshes or revoked.
Flow:

sequence chart
  Client ->> ID port: http get authentication request (/Authorize)
  Note over the ID port: Automatic authentication based on login_hint and implicit consent to scopes
  ID port ->> client: http response with location header with authorization scode
  Client->> ID port: http token request (/token)
  ID port ->> client: id_token + access_token (possibly refresh_token)
  Client ->> API: Use API with Access_token
  API ->> IDPORT: validate token
  ID port ->> API: Token information
  API->> Client: Result of API operation

1: Modified /Authorize-Request
In this simplified flow, a synthetic test user can be automatically logged in by submitting one and list of other common parameters in an authorization request to the ID port.
