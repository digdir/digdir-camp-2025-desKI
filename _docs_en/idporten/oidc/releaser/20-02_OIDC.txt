New functionality:
Endpoint for Revocated Authorizations (Shipped)
There is a new endpoint in OIDC that publishes revocated app authorizations.
The functionality is primarily intended for customers who have apps with very high spread, and/or have very high at the same time use, so that standardized token Introspection to check if an authorization is still valid can make performance challenges
Require all scope to be recorded (shipped)
As of today, customers must follow various procedures depending on whether their integration is to consume scopes directly, versus scopes available to all or scopes that support external delegation.
This is confusing, and therefore we change it so that all Scopes as a client should be able to request, must always be registered on the client.
